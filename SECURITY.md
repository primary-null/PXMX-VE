# Security policy

## Supported versions

Security fixes are developed on `main` and included in subsequent releases. Use
the latest release; older releases do not have a separate security maintenance
branch.

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/primary-null/PXMX-VE/security/advisories/new)
to contact Primary Node. Describe the affected version, the steps needed to
reproduce the issue, and its impact. Use synthetic server and account details.
Do not include live credentials, personal identities, internal addresses, or
device identifiers in a public issue or pull request.

Reports are reviewed as maintainer availability permits. Acknowledgment and fix
dates are not guaranteed; follow-up discussion can stay in the private report.

If a credential has been exposed, revoke or rotate it through its issuer rather
than waiting for a repository update.
